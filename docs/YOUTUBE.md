# YouTube: подключение и первая комплексная проверка

Студия умеет ставить загрузки в отдельную постоянную очередь, отправлять MP4
**приватно**, устанавливать подготовленную обложку и сохранять ID видео.
Публикация по расписанию пока не включена. Авторизация выполняется на вашей VM;
пароли Google, OAuth JSON и токены не нужно присылать в чат или коммитить.

## 1. Обновить студию

Дождитесь завершения текущего выпуска и загрузок.

```bash
systemctl --user stop lofi-web
git -C ~/music_gen pull --ff-only
bash ~/music_gen/scripts/install.sh
systemctl --user start lofi-web
```

Обновите страницу Ctrl+F5. Появится вкладка **YouTube**.
Дополнительные Python-пакеты для загрузчика не требуются.

## 2. Создать OAuth-клиент

1. Откройте https://console.cloud.google.com/ и создайте/выберите отдельный проект
   для Retro Reverie Sounds.
2. В **APIs & Services → Library** включите **YouTube Data API v3**.
3. В **Google Auth Platform** настройте Branding/Audience. Если приложение
   External и Testing, добавьте Google-аккаунт владельца канала в Test users.
4. В Clients создайте **OAuth client ID → Desktop app**. Скачайте JSON.
   Тип Web application для этого способа не подходит.
5. Скопируйте JSON на VM по SSH/SCP как `~/lofi_auto/client_secret.json`.

Например, из PowerShell на Windows (замените исходный путь и IP):

```powershell
scp "$HOME\Downloads\client_secret_ВАШ_ID.json" faa@IP-VM:~/lofi_auto/client_secret.json
```

На VM:

```bash
chmod 600 ~/lofi_auto/client_secret.json
```

Запрашиваются только `youtube.upload` (видео и обложка) и `youtube.readonly`
(проверка канала). Desktop OAuth использует PKCE и callback на loopback;
не используется устаревшая схема копирования кода из Google в терминал.

## 3. Авторизовать нужный канал

Если браузер на Windows, а студия на Linux VM, откройте отдельный PowerShell
и оставьте SSH-туннель работающим:

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 8765:127.0.0.1:8765 faa@IP-VM
```

В другом терминале **на VM** запустите:

```bash
bash ~/lofi_auto/connect_youtube.sh
```

Откройте напечатанную ссылку в браузере Windows. Выберите Google-аккаунт и нужный
канал **Retro Reverie Sounds**, предоставьте оба разрешения. После возврата на
`127.0.0.1:8765` вернитесь в терминал VM: там появятся название и ID канала.
Введите `YES`, только если это правильный канал. Пока подтверждения нет,
прежний токен не заменяется.

Если браузер запущен прямо на VM, SSH-туннель не требуется. Ожидание авторизации —
10 минут. Если порт занят, можно использовать `--port 8766` и соответствующий
туннель с 8766 на обеих сторонах. Не открывайте callback-порт во внешнюю сеть.

Обновите вкладку YouTube в студии: должно появиться имя подключённого канала.
Туннель после подключения можно закрыть. Перезапуск панели не нужен.

## 4. Прогнать настоящий выпуск

1. Для первой проверки используйте готовый короткий MP4: заново генерировать
   музыку не обязательно. Позже проверьте новый выпуск от начала до конца.
2. **Выпуски → Оформление выпуска**: просмотрите обложку, название и описание,
   проверьте таймкоды и сохраните нужные правки.
3. Выберите аудиторию: предназначен ли выпуск специально для детей.
   Поле AI/синтетического контента по умолчанию включено для нашего проекта.
4. Нажмите **Сохранить и загрузить приватно** и проверьте название/ID канала
   в подтверждении.
5. Во вкладке **YouTube** наблюдайте прогресс. Можно закрыть браузер:
   загрузка идёт в службе `lofi-web`.
6. Когда появится ссылка, откройте видео в YouTube Studio. Дождитесь обработки,
   проверьте доступ **Private**, звук, видео, название, описание и обложку.
   Статус «Передано YouTube» означает завершение передачи, а не завершение
   обработки или проверок на стороне YouTube.
7. Повторное нажатие загрузки для того же MP4 и канала должно вернуть прежнюю
   запись, а не создать видео заново. Правки текста после постановки в очередь
   не меняют уже зафиксированный запрос. Изменить опубликованные метаданные
   пока можно вручную в YouTube Studio.

## 5. Поведение при сбоях

- MP4 передаётся блоками по 8 MiB. После обрыва сначала запрашивается принятый
  YouTube диапазон; локальный счётчик не считается источником истины.
- Сетевые ошибки/429/5xx получают до четырёх попыток с задержкой. Затем загрузка
  ждёт нажатия «Продолжить загрузку»; бесконечных повторов нет.
- Перезапуск панели продолжает уже сохранённую сессию. Исходный MP4 проверяется
  по SHA-256; изменённый файл не смешивается с ранее отправленными блоками.
- ID видео записывается **до** отправки обложки. При отказе загрузить обложку
  доступно «Повторить обложку», MP4 повторно не отправляется.
- Если ответ при создании сессии потерян либо сессия истекла, статус будет
  **«Нужна проверка в YouTube Studio»**. Автоматическая новая сессия запрещена:
  сначала нужно выяснить, появилось ли видео. Не удаляйте базу очереди для повтора.
- Если токен истёк/отозван (`invalid_grant`), повторите подключение канала,
  затем продолжите загрузку. Если выбран другой канал, отправка блокируется.
- Возможность загрузить свою обложку зависит от разрешений/состояния канала.
  Ошибка обложки не означает, что видео отсутствует.

## Данные и ограничения

`~/lofi_auto/web_data/youtube/` (или `LOFI_WEB_DATA/youtube/`) содержит токен,
SQLite-очередь, адреса сессий и копии выбранных обложек. Каталог имеет права 700,
токен — 600. Они не выдаются через API панели и исключены из Git. При переносе
сохраняйте каталог целиком вместе с `episodes`, остановив панель. Внешний доступ
к панели должен идти через HTTPS или SSH-туннель, а не открытый HTTP.

У внешнего OAuth-приложения в режиме **Testing** refresh token обычно истекает
через 7 дней с этими scopes. Для длительной автоматизации потребуется разобраться
с production-настройками OAuth. Это отдельно от аудита YouTube API-проекта:
видео от непроверенных API-проектов могут быть ограничены приватным доступом.
Сейчас студия намеренно использует только приватную загрузку.

OAuth не создаёт канал, не обходит квоты и не гарантирует допуск к публичной
публикации. Проверяйте сообщения Google; не отключайте защиту аккаунта.

## Проверки без Google

```bash
~/ACE-Step-1.5/.venv/bin/python -m unittest discover -s ~/music_gen/tests -v
```

Тесты используют синтетические WAV, настоящий FFmpeg и симулятор Google HTTP API.
Проверяются веб-очередь → MP4 → оформление → запрос загрузки, OAuth callback,
state/PKCE, приватность, фиксированные метаданные, дедупликация, потерянный ответ,
продолжение по серверному смещению, ошибки обложки и смена канала. Они не вызывают
ACE-Step и не обращаются к реальному Google-аккаунту. Реальное качество музыки,
авторизация, квота и обработка YouTube проверяются владельцем по шагу 4.
