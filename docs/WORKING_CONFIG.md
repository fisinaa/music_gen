# Проверенный профиль VM

| Компонент | Значение |
| --- | --- |
| ОС | Ubuntu 22.04.5 LTS |
| VM | 18 vCPU, около 47 GiB RAM |
| GPU | GTX 1660 SUPER, 6 GB, compute capability 7.5 |
| PyTorch | 2.10.0+cu128 |
| Python ACE-Step | 3.11.16, `~/ACE-Step-1.5/.venv` |
| ACE-Step | пользовательский checkout, базовый commit `ca1e85f` |
| DiT / текстовый энкодер | CPU, FP32, без квантизации |
| VAE | CUDA FP32, chunk 128, overlap 32; затем возврат на CPU |
| Генерация | turbo, 8 steps, batch 1, LLM выключен |
| Длительность | случайные 180–240 секунд |
| WAV | 48 kHz, stereo, PCM 16 bit |
| Сервер | порт 7860, существующий Gradio API из `api_snapshot.json` |
| Служба | 12 vCPU, Nice 10, MemoryHigh 32G, MemoryMax 36G, SwapMax 1G |

Точная команда сервера находится в `lofi_auto/run_ace.sh`, ресурсы службы —
в `lofi_auto/setup.sh`. Сначала устанавливается сервис, затем `create` запускает
его только если сервер на порту 7860 ещё не доступен.

`ACESTEP_VAE_ON_GPU=1` и `ACESTEP_VAE_ON_CPU=1` совместимы в нашем патче:
новый GPU-путь имеет приоритет. DiT остаётся на CPU; простой GPU в этой фазе нормален.
Исходная версия ACE-Step не применяла `ACESTEP_DTYPE` для CUDA — одного этого
параметра было недостаточно. Текущий профиль избегает DiT FP16 на GTX 1660.

## Известные проблемы и решения

- NaN/Inf в FP16: VAE выполняется в FP32 с отключённым autocast.
- 180-секундная генерация не помещалась в 6 GB: DiT переведён на CPU.
- CPU VAE занимал около 9:37: чанковое декодирование перенесено на GPU (~22 секунды).
- WAV возвращался только в Gradio All Generated Files: очередь v1.1 ищет оба пути
  выдачи и удаляет дубли по содержимому.
- После разрыва клиента задача могла продолжать работать: автоматическая повторная
  отправка запрещена до проверки сервера; есть явный `--retry-interrupted`.
- Сохранение моделей в RAM после генерации нормально: сервер остаётся запущен.

## Фоны и монтаж

Пять сцен идут равными частями: для 30 минут по 6 минут на каждую.
Между сценами трёхсекундное растворение; дождь/туман только утром и вечером,
пар отсутствует в обеденной сцене. Циклы анимации кешируются.
Музыкальные стыки перекрываются на 6 секунд; цель громкости -18 LUFS / -1.5 dBTP.
Монтаж CPU, libx264, до 4 потоков кодировщика. GPU зарезервирован для VAE.
