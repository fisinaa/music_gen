# Проверки интеграции YouTube — 2026-10-06

## Выполнено

`python3 -m unittest discover -s tests -v`: **24 теста, OK**, 47.796 секунды.

- Веб-аутентификация, запрет стороннего Origin, проверка путей и Range-запросов.
- Постоянная очередь, один исполнитель, пауза, отмена, восстановление прерванного состояния.
- Даты музыки, повторный импорт, учёт перекрытий в длительности.
- Реальное сведение синтетических WAV и настоящий 30-секундный MP4 через FFmpeg.
- Автоматическое оформление и сохранение отредактированных текстов.
- Полная интеграция через HTTP API студии: задача → MP4 → оформление → загрузчик.
- OAuth loopback callback, отклонение неверного state, PKCE, подтверждение канала.
- Приватная загрузка, снимок метаданных, дедупликация одинакового MP4 на одном канале.
- Обрыв после принятого блока и после последнего блока: восстановление по серверному состоянию.
- Ошибка обложки и её повтор без повторной отправки видео.
- Перезапуск загрузчика, обновление токена, другой канал, изменившийся файл.
- Истечение сессии / потерянный ответ инициализации: остановка для ручной проверки.
- Токены и адрес сессии не попадают в публичный JSON; перенаправления HTTP не следуются.

Google API в этих тестах заменён управляемым симулятором. Это проверка нашей
логики и протокола запросов, а не результат настоящей загрузки на YouTube.

Дополнительно выполнены `node --check`, `py_compile`, `bash -n`, `git diff --check`.

Повторная загрузка дополнительно проверена: новое видео с новым ID и актуальным
оформлением; неизменность старой записи; два одновременных запроса создают одну
задачу; активная загрузка блокирует новый повтор; миграция прежней SQLite-схемы
сохраняет ID, адрес сессии и смещение и допускает повторный запуск мигратора.
Проверен также HTTP-маршрут повторной загрузки с обязательным подтверждением.

Выбор доступа дополнительно проверен: отправка `public`, `unlisted`, `private`,
публичная повторная загрузка через HTTP API панели, валидация недопустимых режимов,
отображение несовпадения запрошенного и возвращённого Google доступа. Повторный
запрос с другим режимом не выдаётся за успешную смену доступа существующей записи.

## Требует проверки на VM владельца

- Реальные OAuth-разрешения, выбор Retro Reverie Sounds, квоты и доступность Google.
- Приём и обработка MP4, применение обложки, просмотр результата в YouTube Studio.
- Отображение новых элементов и действия в браузере: автоматический браузерный
  прогон здесь не состоялся, поскольку Chromium отсутствует, а скачивание его
  дистрибутива завершилось ошибкой архива. Проверка синтаксиса JS прошла.
- Генерация ACE-Step и субъективное качество звука: тесты используют синтетическое
  аудио и не запускают модель/GPU. Рабочий профиль модели не менялся.

Пошаговая проверка настоящего короткого выпуска описана в [YOUTUBE.md](YOUTUBE.md).
