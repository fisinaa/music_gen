# RTX 3060 12 GB: пробный GPU-профиль

Предыдущий запуск оставлял DiT на CPU. Замена карты сама по себе это не меняет.
Новый профиль переводит DiT и штатный VAE на CUDA; ACE-Step выбирает dtype
самостоятельно (базовый ca1e85f выбирает BF16 на совместимой CUDA-карте).
Это эксперимент: скорость, память и звучание на конкретной VM ещё не измерены.

## Установка с точкой возврата

Дождитесь окончания выпуска и приостановите очередь в панели. Не перезапускайте
ACE во время генерации. Команды ниже выполняются на Ubuntu VM:

```bash
cd ~/music_gen
git fetch origin
git switch feature/rtx3060-generation
python3 scripts/checkpoint.py --destination "$HOME/lofi-before-rtx3060-$(date +%Y%m%d-%H%M%S)"
bash scripts/install.sh
```

Сохраните напечатанный путь checkpoint. Он содержит код, config.env и сцены,
но не виртуальное окружение ACE, модели, службу, базу очереди и токены.
Установка сохраняет config.env и сама не перезапускает ACE. Модели, PyTorch,
драйвер, torchao и ACE-Step обновлять для этого изменения не нужно.

В `~/lofi_auto/config.env` задайте `LOFI_ACE_PROFILE=rtx3060`.
Для добавления в конец существующего файла:

```bash
printf '\nLOFI_ACE_PROFILE=rtx3060\n' >> ~/lofi_auto/config.env
bash ~/lofi_auto/run_ace.sh --check
systemctl --user restart lofi-ace.service
systemctl --user restart lofi-web.service
journalctl --user -u lofi-ace.service -n 80 --no-pager
```

Если `--check` завершился ошибкой, не выполняйте restart: сначала проверьте
драйвер и passthrough. Диагностика показывает GPU, VRAM, BF16, torch/CUDA и
ревизию ACE без загрузки моделей. В журнале запуска ожидается `device=cuda`;
также проверьте фактический Dtype и отсутствие CPU fallback.

| Профиль запуска | Поведение |
| --- | --- |
| stable (по умолчанию) | Прежний CPU DiT, патч GPU VAE FP32 |
| rtx3060 | CUDA, выгрузка моделей и DiT на CPU между фазами; первый тест |
| rtx3060-resident | CUDA, DiT остаётся на GPU; пробовать после успешного теста 240 секунд |

Во всех режимах turbo / 8 шагов / batch 1 / без LM и квантизации. Так сначала
можно оценить ускорение без смены модели и установки зависимостей.
Режим resident может экономить пересылки CPU↔GPU, но повышает расход VRAM;
он не гарантированно быстрее и не гарантированно помещается на длинных треках.
Старый патч остаётся на диске для отката, но его CPU-only ветка отключена в CUDA-режимах.

## Сравнение звучания и скорости

В панели выберите chillout, lounge или ambient и запустите сравнение трёх
музыкальных профилей. `stable` сохраняет контрольные промпты, `melodic` и
`dialogue` теперь чередуют три состава инструментов и шесть вариантов гармонии.
Имена профиля запуска и музыкального профиля независимы.
Промпт задаёт пожелания модели, а не гарантирует точную композицию.

Для короткого теста из CLI (при свободной очереди):

```bash
~/lofi_auto/lofi create --style chillout --profile melodic --audition --seed-base 3060
```

Сначала прослушайте две 90-секундные пробы. Затем проверьте обычный выпуск с
треками 180–240 секунд: короткая проба не доказывает, что длинный трек помещается.
Для сравнения stable/rtx3060 используйте одинаковые музыкальный профиль, seed
и длительность. Первый запуск включает прогрев, сравнивайте также повторный.
Зафиксируйте время генерации, пиковую VRAM (`nvidia-smi -l 1` в другом терминале),
ошибки и слышимые дефекты; смена устройства может менять звук даже с тем же seed.
Новая карта сама по себе не добавляет музыкального разнообразия.
LM-планировщик — отдельный следующий эксперимент после проверки GPU-профиля;
включать только серверный LM недостаточно: очередь сейчас отключает thinking.

## Возврат

При свободной очереди верните `LOFI_ACE_PROFILE=stable` в config.env и
перезапустите `lofi-ace.service`. Для возврата также прежних промптов/кода:

```bash
python3 ~/music_gen/scripts/checkpoint.py --restore /полный/путь/из/Checkpoint
systemctl --user restart lofi-ace.service
systemctl --user restart lofi-web.service
```

Проверьте фактическое имя веб-службы через `systemctl --user list-units 'lofi*'`.
Checkpoint не удаляет новые файлы и не откатывает историю выпусков.
