# Lo-fi Auto 1.0 — локальный выпуск одной командой

Для проверенной VM: Ubuntu 22.04, 18 vCPU, ~48 GB RAM, GTX 1660 SUPER 6 GB.
Использует установленный ACE-Step и **уже работающий патч VAE GPU FP32**.
DiT остаётся на CPU; VAE — на GPU, float32, chunk 128. Патч и модели этот архив не меняет.

## Установка один раз

Распакуйте архив в домашнюю папку, получится `~/lofi_auto`:

```bash
cd ~
unzip Lofi_Auto_v1.zip
cd ~/lofi_auto
bash setup.sh
```

Нужны FFmpeg/ffprobe, numpy, Pillow и gradio_client в `~/ACE-Step-1.5/.venv`.
Обычно они уже есть после наших прошлых шагов. Если отсутствует FFmpeg:
`sudo apt install ffmpeg`. Не переустанавливайте PyTorch ради этой программы.

`setup.sh` проверяет зависимости и устанавливает пользовательскую службу
`lofi-ace.service`; не запускает второй сервер и не останавливает текущий.
Служба использует 12 vCPU, Nice=10, MemoryHigh=32G, MemoryMax=36G, SwapMax=1G.
Каталог проекта после установки службы не переносите без повторного `setup.sh`.

## Общая папка с названиями треков

Готовые проверенные треки автоматически копируются в `~/lofi_auto/music`:
`Quiet_Window_a83f216b74.wav`, `Misty_Coffee_94ae307c21.wav` и т. п.
Случайные сочетания слов привязаны к содержимому WAV, поэтому имя не меняется
при перезапуске, а одинаковый файл не экспортируется повторно.
Короткий идентификатор предотвращает совпадение имён. `catalog.json` хранит
названия, исходные пути, seed и промпты. Название задаёт настроение, а не
определяется анализом звучания.

Собрать уже готовые треки в эту папку без генерации и монтажа:

```bash
./lofi collect --tracks ~/lofi_queue/runs/morning_long
```

Другая общая папка задаётся через `--music-dir ~/Music/lofi` у любой команды.
`create` экспортирует каждый трек сразу после успешной генерации;
`build` экспортирует все прошедшие проверку треки, включая запасные.
Служебные исходники очереди остаются на месте для проверки и продолжения работы.
Таким образом, общая папка занимает дополнительное место, но не нарушает очередь.
В текстовом треклисте выпуска теперь тоже используются эти названия.

При обновлении распакуйте архив поверх `~/lofi_auto` через `unzip -o`.
Папки музыки, выпусков и кеша в архив не входят и при распаковке сохраняются.

## Сейчас: собрать 30 минут из готовой очереди

```bash
cd ~/lofi_auto
./lofi build \
  --tracks ~/lofi_queue/runs/morning_long \
  --name cafe_day_001 \
  --minutes 30
```

Если готовая очередь лежит в другом каталоге, замените только `--tracks`.
Ожидается структура `track_001_s.../audio.wav` с манифестами очереди.
Также поддерживается отдельная папка, где WAV лежат непосредственно внутри.
Программа не ищет WAV в `downloads`, чтобы не продублировать треки.
Оригиналы сохраняются без изменений.

## Следующий выпуск: музыка + монтаж автоматически

```bash
cd ~/lofi_auto
./lofi create --name cafe_day_002 --minutes 30
```

Программа сама:

1. Сохраняет задания: разные seed, длительность 180–240 секунд, 6 вариаций Morning/Cafe.
2. Подключается к работающему ACE-Step. Если сервер недоступен — запускает установленную службу и ждёт готовности.
3. Последовательно генерирует WAV, batch=1, 8 steps, LLM выключен.
4. Проверяет формат, контрольные суммы, NaN/Inf, тишину, чрезмерный клиппинг и DC.
5. Подбирает достаточно музыки, подрезает тихие края и выравнивает громкость.
6. Сводит с шестисекундными перекрытиями, финальная цель -18 LUFS / -1.5 dBTP.
7. Анимирует 5 готовых сцен: утро → позднее утро → обед → закат → вечер.
8. Собирает MP4 и полностью декодирует его для технической проверки.

Готовые файлы:

```text
episodes/cafe_day_002/episode.mp4       видео H.264, 1600×900, 24 fps, AAC 192k
episodes/cafe_day_002/mix.wav           WAV 16 bit, 48 kHz, stereo
episodes/cafe_day_002/tracklist.txt     время начала треков и seed
episodes/cafe_day_002/tracklist.json    исходники, промпты и проверки
episodes/cafe_day_002/status.json       текущий этап / ошибка / done
episodes/cafe_day_002/work/             журналы и промежуточные результаты
```

Музыка не повторяется для заполнения времени. При недостатке пригодных треков
программа останавливается и пишет причину в `work/quality_report.json`.
`create` генерирует запас длительности, но не запускает бесконечные попытки при ошибках.
Обычно остаются неиспользованные треки; они остаются в `episodes/ИМЯ/tracks`.

## Повторный запуск и ошибки

Повторите **ту же команду с тем же именем** — задания и seed сохранятся,
готовая музыка проверится, завершённые этапы монтажа пропустятся.
Для нового выпуска используйте новое имя. Смена настроек существующего выпуска
останавливает программу, чтобы случайно не перезаписать результат другой сборкой.
Одновременно работает только один конвейер. Не генерируйте параллельно через веб-интерфейс.

Ошибки генерации требуют прочесть `tracks/track_.../manifest.json`.
После устранения причины `--retry-failed` разрешает повторить явно провалившееся задание.
При обрыве соединения неизвестно, закончил ли сервер работу:
**сначала убедитесь, что старая генерация завершилась, или перезапустите ACE-Step**,
только затем повторите команду с `--retry-interrupted`.
При прерывании монтажа эти флаги не нужны.

```bash
journalctl --user -u lofi-ace -n 80
journalctl --user -u lofi-ace -f
systemctl --user stop lofi-ace
```

`stop` останавливает только сервер новой службы. Если сервер запущен прежней
командой в терминале, он управляется тем терминалом. Программа его не убивает.
Сервер остаётся в памяти между выпусками для быстрого следующего запуска.

Для работы после отключения SSH можно запускать команду в `tmux`:

```bash
tmux new -s lofi
cd ~/lofi_auto
./lofi create --name cafe_day_003 --minutes 30
# Отсоединение: Ctrl+B, затем D. Возврат: tmux attach -t lofi
```

Автозапуск по расписанию и публикация в YouTube в этой версии не включены.

## Визуальная часть и ресурсы

Пять изображений входят в архив. Пар мягкий, капли замедлены, дождь и лёгкий туман
есть утром и вечером. Обед без пара. Между сценами — трёхсекундное растворение.
В течение каждой сцены повторяется короткая анимация со сглаженным стыком;
это не длинное генеративное видео. На первом запуске создаётся общий кеш анимаций.
Повторные выпуски используют его. Новые изображения автоматом не генерируются:
новый интерьер/стиль добавляется отдельным набором сцен.

Монтаж выполняется FFmpeg на CPU, до 4 потоков кодировщика; GPU для него не нужен.
Генерация и монтаж идут последовательно. Нужно несколько GB свободного диска на
выпуск с промежуточными файлами; оставьте хотя бы 8 GB запаса для 30 минут.
Время рендера зависит от CPU, отдельно от времени генерации музыки.

Для ускоренного визуального теста из существующей музыки:

```bash
./lofi build --tracks ~/lofi_queue/runs/morning_long \
  --name preview_01 --minutes 0.5 --width 640 --loop-seconds 4
```

Автоматические проверки находят технический брак, но не оценивают мелодию,
однообразие или музыкальные запинки. Первый полный выпуск стоит прослушать.

## Что проверено при сборке

Локально проверяется короткий выпуск с реальным ранее одобренным аудио:
сведение нескольких WAV, нормализация, все 5 сцен, MP4 с аудио, полное декодирование,
повторный запуск без пересборки, отказ при тишине и нехватке материала.
Живой API вашей VM из среды сборки недоступен; здесь используется прежний
адаптер очереди v1.1 с проверкой Gradio API до отправки задания.
